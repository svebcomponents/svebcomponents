:::

The same custom element runs in Svelte, Vue, React, Astro, or a plain HTML page.
Each server framework needs an integration that routes `<my-component>` to its
`ElementRenderer` and emits markup the framework can hydrate. The element
[hydrates](/server-rendering/hydration/) its shadow root in the browser.

## Server output

On the server, an integration emits the element with its shadow root inline:

```html
<my-component title="Hello">
  <template shadowrootmode="open"><!-- shadow content --></template>
  <!-- light dom children -->
</my-component>
```

The HTML parser requires `<template shadowrootmode>` as the element's first
child. It adopts the template into a shadow root and removes it from the light
DOM before scripts run.

In the browser, the integration omits the consumed template. The host framework
hydrates against the remaining child list, while the element hydrates its
shadow root.

## Svelte

A Vite plugin rewrites custom element tags in `.svelte` templates to a wrapper
component. The [SSR guide](/server-rendering/) covers the setup:

```ts
import { sveltekit } from "@sveltejs/kit/vite";
import svebcomponents from "@svebcomponents/ssr/vite";
import { defineConfig } from "vite";

export default defineConfig({
  plugins: [svebcomponents(), sveltekit()],
});
```

Svelte provides separate synchronous and asynchronous wrappers. The async
wrapper uses `await` in the template, so compile the host app with
`compilerOptions.experimental.async`.

## Vue

Install `@svebcomponents/ssr-vue` and add its Vite plugin ahead of
`@vitejs/plugin-vue`:

```ts
import vue from "@vitejs/plugin-vue";
import svebcomponentsVue from "@svebcomponents/ssr-vue/vite";
import { defineConfig } from "vite";

export default defineConfig({
  plugins: [svebcomponentsVue(), vue()],
});
```

Register the wrapper component on both the server and client app instances:

```ts
import { svebcomponents } from "@svebcomponents/ssr-vue";

app.use(svebcomponents());
```

Then write custom elements in any single-file component:

```vue
<template>
  <my-component title="Hello" :count="5" />
</template>
```

### Async rendering

Vue's `renderToString` awaits an async `setup()` before emitting output, so one
wrapper handles synchronous and asynchronous element renderers. An
[asynchronous component](/server-rendering/#asynchronous-components)
needs nothing extra here beyond the
[`enable-async` opt-in](/server-rendering/#async-rendering-outside-svelte)
every non-Svelte host needs.

### Vite transform

Vue runs user `compilerOptions.nodeTransforms` after its built-in transforms.
By then, `@vue/compiler-ssr` has resolved the component identity and ignores a
renamed tag on the server.

Rewriting the single-file component's source before `@vitejs/plugin-vue` sees
it means the client and server compiles observe the same template.

## React

Install `@svebcomponents/ssr-react` and point the JSX transform at it:

```jsonc
// tsconfig.json
{
  "compilerOptions": {
    "jsx": "react-jsx",
    "jsxImportSource": "@svebcomponents/ssr-react",
  },
}
```

The JSX runtime routes tags containing a dash through the integration:

```tsx
<my-component title="Hello" count={5} />
```

The JSX runtime setting works in React setups that do not use Vite.

You can use the wrapper without changing the JSX runtime:

```tsx
import { CustomElement } from "@svebcomponents/ssr-react";

<CustomElement tag="my-component" title="Hello" count={5} />;
```

### Async rendering with RSC

React's `renderToString` cannot await, so an
[asynchronous component](/server-rendering/#asynchronous-components)
cannot be server-rendered by the default `CustomElement`.

For an async element, the default wrapper emits the host tag without shadow
content and logs one warning. The browser renders the component. Configuration
errors, such as a missing renderer, still throw.

Apps on a React Server Components framework can server-render these elements
instead, from a Server Component:

```tsx
import { CustomElement } from "@svebcomponents/ssr-react/rsc";

<CustomElement tag="my-component" title="Hello" count={5} />;
```

An RSC async function component can await the renderer before it emits markup.
It accepts
[asynchronous components](/server-rendering/#asynchronous-components)
in either form (given the
[`enable-async` opt-in](/server-rendering/#async-rendering-outside-svelte)
every non-Svelte host needs for that).

The RSC wrapper works from Server Components. Client Components cannot import
an async function component, so they use the default browser-rendered fallback.

## Astro

Add the integration:

```ts
import { defineConfig } from "astro/config";
import svebcomponents from "@svebcomponents/ssr-astro";

export default defineConfig({
  integrations: [svebcomponents()],
});
```

Custom elements then work in any `.astro` template:

```astro
<my-component title="Hello" count="5">
  <p>light dom child</p>
</my-component>
```

### Browser behavior

Astro ships no host JavaScript for these elements. The parser attaches the
shadow root, then the element upgrades and hydrates when its bundle loads.

The exception is islands. A custom element inside a `client:*` React, Vue or
Svelte island belongs to that framework, and the corresponding integration
applies there instead.

### Async rendering

Astro frontmatter runs in an async module scope, so the wrapper awaits the
element renderer.
[asynchronous components](/server-rendering/#asynchronous-components)
need nothing extra beyond the
[`enable-async` opt-in](/server-rendering/#async-rendering-outside-svelte)
every non-Svelte host needs.

## Other Frameworks

The pieces an integration is built from are exported for reuse:

```ts
import {
  renderCustomElement,
  renderCustomElementSync,
} from "@svebcomponents/ssr";

const { attributes, shadowTemplate, shadowContent } = await renderCustomElement(
  "my-component",
  { title: "Hello" },
);
```

Use `renderCustomElementSync` when the host cannot await. It throws
`AsyncRendererError` for an async element, allowing the host to choose a
fallback. Use `renderCustomElement` when the host can await. `shadowTemplate` is the complete
`<template shadowrootmode="open">…</template>` string for hosts that emit raw
markup; `shadowContent` is its inner markup, for hosts that build the template
element themselves.

The pipeline renders [any custom element with a registered
renderer](/server-rendering/#other-custom-elements) through Lit's
`ElementRenderer` contract.

## Requirements

`@svebcomponents/ssr` calls Svelte's server renderer, so `svelte` must be
installed as a server-side dependency of the host application even when it
contains no Svelte components of its own. See
[Compatibility](/reference/compatibility/) for every host's version
requirements.
