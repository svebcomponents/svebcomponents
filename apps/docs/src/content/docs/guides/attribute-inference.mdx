---
title: Attribute inference
description: Generate Svelte custom-element prop options from TypeScript types.
---

Svelte's
[`customElement.props`](https://svelte.dev/docs/svelte/custom-elements#Component-options)
option tells its custom-element wrapper how to convert attributes and reflect
properties. `@svebcomponents/auto-options` generates that Svelte option from
the TypeScript types in `$props()`.

## Input

```svelte
<script lang="ts">
  interface Props {
    label: string;
    value: number;
    featured: boolean;
  }

  let { label, value, featured }: Props = $props();
</script>
```

Before Svelte compiles the component, `auto-options` turns that declaration
into:

```svelte
<svelte:options
  customElement={{
    props: {
      label: { attribute: "label", reflect: true, type: "String" },
      value: { attribute: "value", reflect: true, type: "Number" },
      featured: { attribute: "featured", reflect: true, type: "Boolean" },
    },
  }}
/>
```

Svelte then converts `value="42"` to the number `42`. The
`@svebcomponents/build` pipeline runs this transform for you.

## What it infers

| Svelte prop type           | Custom element type                    |
| -------------------------- | -------------------------------------- |
| `string`                   | `"String"`                             |
| `number`                   | `"Number"`                             |
| `boolean`                  | `"Boolean"`                            |
| string/number/bool literal | `"String"`, `"Number"`, or `"Boolean"` |
| `SomeType[]`, `Array<T>`   | `"Array"`                              |
| object literals, `Record`  | `"Object"`                             |
| interface references       | `"Object"`                             |

Props without type information use Svelte's `"String"` default. Attribute
names use kebab case, so `favoriteNumber` becomes `favorite-number`.

The transform expands Svelte's string shorthand and merges the inferred
`props`:

```svelte
<svelte:options customElement="favorite-number" />
```

## Overriding what it infers

Options you write take precedence. Override an attribute name, type, or
reflection behavior in `<svelte:options>`:

```svelte
<svelte:options
  customElement={{
    props: {
      value: { type: "Number", attribute: "data-value", reflect: false },
    },
  }}
/>
```

`auto-options` preserves those fields and fills in the rest.

For supported prop shapes, standalone plugin setup and current limitations, see
the [`@svebcomponents/auto-options` reference](/packages/auto-options/).
