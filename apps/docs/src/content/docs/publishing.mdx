---
title: Publishing your package
description: Declare component exports, types, the manifest, and server output.
---

The CLI reads `package.json` exports to find source components and choose build
targets. Consumers use the same exports to load the output.

## Export each component

Match each browser output to a same-basename file in `src`:

```json
{
  "exports": {
    ".": {
      "types": "./dist/client/FavoriteNumber.d.ts",
      "default": "./dist/client/FavoriteNumber.js"
    },
    "./color-picker": {
      "types": "./dist/client/ColorPicker.d.ts",
      "default": "./dist/client/ColorPicker.js"
    }
  }
}
```

The second export builds `src/ColorPicker.svelte`. A matching `.ts` or `.js`
file creates a standard JavaScript entry. See the full
[entrypoint rules](/guides/build/#entrypoints-from-package-exports).

## Publish the manifest

The build writes a
[custom elements manifest](https://github.com/webcomponents/custom-elements-manifest)
for editors and other custom-element tooling:

```json
{
  "customElements": "custom-elements.json",
  "files": ["dist", "custom-elements.json"]
}
```

## Publish Svelte template types

The declaration for each component types its DOM class and registers its tag in
`HTMLElementTagNameMap`. The build also writes a `svelte/elements`
augmentation for Svelte templates:

```text
dist/client/FavoriteNumber.svelte-types.d.ts
```

Packages that require consumers to install Svelte reference this file from the
main declaration. Other packages can expose it as an opt-in:

```json
{
  "exports": {
    "./svelte": {
      "types": "./dist/client/FavoriteNumber.svelte-types.d.ts"
    }
  }
}
```

Consumers import that entry from a project declaration file:

```ts
// app.d.ts
import "my-components/svelte";
```

React and Vue projects need a framework augmentation. See
[Typing elements in React and Vue](/guides/framework-types/).

## Share the Svelte runtime

The `default` output includes the Svelte runtime for use in any application. A
`svelte` condition creates another output that shares the host application's
runtime:

```json
{
  "exports": {
    ".": {
      "types": "./dist/client/FavoriteNumber.d.ts",
      "svelte": "./dist/client-svelte/FavoriteNumber.js",
      "default": "./dist/client/FavoriteNumber.js"
    }
  }
}
```

:::caution[Version coupling]
Compiled components call private Svelte runtime APIs. Build the package and
host application with the same Svelte version when you use this condition.
:::

## Add server output

Add `/ssr` to a component's export key:

```json
{
  "exports": {
    "./color-picker": {
      "types": "./dist/client/ColorPicker.d.ts",
      "default": "./dist/client/ColorPicker.js"
    },
    "./color-picker/ssr": {
      "types": "./dist/server/ColorPicker.ssr.d.ts",
      "default": "./dist/server/ColorPicker.ssr.js"
    }
  }
}
```

The build generates an `ElementRenderer` at the server path. Give each server
entry a distinct filename when components share an output directory. Continue
with [Server rendering](/server-rendering/).
