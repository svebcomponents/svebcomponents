title: Authoring components
description: Define the props, events, slots, and styles exposed by a built component.
---

Write a Svelte component, then declare the tag that the custom-element build
will register. The
[Svelte custom elements guide](https://svelte.dev/docs/svelte/custom-elements)
documents the compiler behavior behind this file.

svebcomponents reads the source to generate attribute options, element types,
and manifest entries.

Declare the element tag with `<svelte:options>`:

```svelte
<svelte:options customElement="favorite-number" />
```

## Props and attributes

Declare typed props with Svelte's `$props()` rune:

```svelte
<script lang="ts">
  interface Props {
    /** Number of items shown on each page. */
    pageSize: number;
    featured?: boolean;
  }

  let { pageSize, featured = false }: Props = $props();
</script>
```

The generated element exposes these props as JavaScript properties.
`@svebcomponents/auto-options` also writes `customElement.props` metadata for
their attribute names, conversion, and reflection. It derives that metadata
from the TypeScript declaration above.

The generated attribute names use kebab case:

| Property   | Attribute   |
| ---------- | ----------- |
| `pageSize` | `page-size` |
| `featured` | `featured`  |

## Events

Use Svelte's [`$host()`](https://svelte.dev/docs/svelte/$host) rune to dispatch
an event from the custom element:

```svelte
<script lang="ts">
  function change(value: string) {
    $host().dispatchEvent(
      new CustomEvent("change", { detail: { value } }),
    );
  }
</script>
```

The build adds statically named `CustomEvent` calls to the generated event map.

## Slots

Use `<slot>` for light DOM content:

```svelte
<div class="card">
  <slot name="header"></slot>
  <slot></slot>
</div>
```

```html
<my-card>
  <h2 slot="header">Title</h2>
  <p>Body</p>
</my-card>
```

The manifest records each named slot. Server-rendered components with slots
[mount again during upgrade](/server-rendering/hydration/#slots).

## Styles

In custom-element mode, the compiler puts component styles in the shadow root.
Use `:host` for the element and CSS custom properties for values consumers can
change:

```svelte
<style>
  :host {
    display: inline-block;
    border-radius: var(--card-radius, 4px);
  }
</style>
```

The manifest records CSS custom properties that the component reads.

## Manifest descriptions

JSDoc on a prop becomes its description. Add descriptions for the component,
slots, events, or CSS properties in an `@component` comment:

```svelte
<!-- @component
A button with a configurable corner radius.

@slot - Button label.
@event change - Fired after the value changes.
@cssprop --button-radius - Corner radius.
-->
```
