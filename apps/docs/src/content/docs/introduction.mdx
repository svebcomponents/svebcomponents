description: How Svelte turns a component into a custom element, and where svebcomponents fits.

Svelte can compile a component into a custom element:

```svelte
<svelte:options customElement="favorite-number" />

<script lang="ts">
  let { value = 0 }: { value?: number } = $props();

  function change(value: number) {
    $host().dispatchEvent(new CustomEvent("change", { detail: value }));
  }
</script>

<button onclick={() => change(value + 1)}>{value}</button>
```

Compile it with Svelte's `customElement: true` option. Importing the result
registers `<favorite-number>` with the browser. Svelte creates the custom
element class, exposes props on the element, attaches a shadow root, and
connects the component lifecycle.

`<svelte:options>`, `$props()`, `$host()`, slots, and component styles are
Svelte APIs. Read Svelte's
[custom elements guide](https://svelte.dev/docs/svelte/custom-elements) before
using svebcomponents.

### TL;DR

Svelte wraps the compiled component in an `HTMLElement` subclass. The browser
creates that class when it upgrades the matching tag. Svelte mounts the
component inside its shadow root and maps element properties and attributes to
component props.

Svelte needs `customElement.props` metadata to convert attribute strings into
numbers, booleans, arrays, or objects. It also mounts custom elements in the
browser, so its standard output cannot preserve server-rendered shadow DOM.
Those two constraints account for much of the setup in a component library.

## Where svebcomponents fits

Building a library adds repetitive prop metadata, packaging, consumer types,
and server output. svebcomponents supplies that tooling around Svelte:

| Need                                                          | Provided by                    |
| ------------------------------------------------------------- | ------------------------------ |
| Custom element class and lifecycle                            | Svelte                         |
| Props, events, slots, and styles                              | Svelte                         |
| Attribute metadata inferred from `$props()` types             | `@svebcomponents/auto-options` |
| Browser bundles, declarations, and a custom elements manifest | `@svebcomponents/build`        |
| Declarative shadow DOM and hydration                          | `@svebcomponents/ssr`          |
| Svelte, React, Vue, and Astro SSR adapters                    | svebcomponents integrations    |

svebcomponents keeps Svelte's authoring model. You write a Svelte custom
element; the toolkit packages it for use across frameworks.

:::note[Beta]
svebcomponents is in beta. APIs may change before 1.0.
:::
