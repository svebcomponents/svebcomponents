Svelte has a compiler mode for custom elements. Start by declaring a tag on the
component:

```svelte
<svelte:options customElement="favorite-number" />

<script lang="ts">
  let { value = 0 }: { value?: number } = $props();

  function change(value: number) {
    $host().dispatchEvent(new CustomEvent("change", { detail: value }));
  }
</script>

<button onclick={() => change(value + 1)}>{value}</button>
```

Set `customElement: true` in the Svelte compiler options. The compiler emits an
`HTMLElement` class around the component. Because this example declares a tag,
importing the compiled module registers `<favorite-number>` in the browser.

The official
[custom elements guide](https://svelte.dev/docs/svelte/custom-elements)
documents the compiler mode, `<svelte:options>`, `$host()`, prop options, and
the generated element's lifecycle. Read it before the rest of these docs.

### TL;DR

The compiler wraps the component in an `HTMLElement` subclass. The browser
creates an instance when it upgrades the matching tag. The wrapper mounts the
component inside a shadow root and connects element properties and attributes
to component props.

The `customElement.props` compiler option controls attribute conversion and
reflection. Writing that metadata by hand repeats information from your
TypeScript props. The generated wrapper mounts in the browser; it does not
produce or adopt declarative shadow DOM on the server.

## Where svebcomponents fits

`@svebcomponents/build` configures custom-element compilation, discovers
entries from package exports, and produces the browser bundles. It also emits
element declarations and a custom elements manifest.

`@svebcomponents/auto-options` turns `$props()` types into
`customElement.props` metadata. The SSR packages generate declarative shadow
DOM, preserve it during upgrade, and connect the result to Svelte, React, Vue,
or Astro hosts.

You write Svelte components and declare their tags. svebcomponents handles the
library around them.
