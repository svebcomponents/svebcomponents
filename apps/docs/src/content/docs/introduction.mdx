[Svelte has a compiler mode for custom elements](https://svelte.dev/docs/svelte/custom-elements).
Building a library with it takes more work: you have to supply attribute
metadata, configure several build targets, generate consumer types, and handle
server rendering.

svebcomponents is a toolkit for boilerplate-free, type-safe, server-renderable
web components with Svelte. It adds:

- `customElement.props` metadata inferred from your `$props()` types
- browser and server builds derived from package exports
- TypeScript declarations and a custom elements manifest
- host adapters that emit declarative shadow DOM, plus a custom-element
  extension that hydrates it

You declare each component API once in Svelte. svebcomponents configures the
compiler and generates the package around it.

## One component, complete package

Start with a Svelte component and a custom-element tag:

```svelte
<svelte:options customElement="favorite-number" />

<script lang="ts">
  let { value = 0 }: { value?: number } = $props();

  function increment() {
    value += 1;
    $host().dispatchEvent(new CustomEvent("change", { detail: value }));
  }
</script>

<button onclick={increment}>{value}</button>
```

svebcomponents reads your package exports to choose build entries. From this
source, svebcomponents can generate:

| Output                         | Consumer                                  |
| ------------------------------ | ----------------------------------------- |
| standalone browser bundle      | HTML and framework apps                   |
| element and event declarations | TypeScript and editors                    |
| `custom-elements.json`         | web-component tooling                     |
| server renderer                | SvelteKit, React, Vue, and Astro adapters |

The generated declarations extend `HTMLElementTagNameMap`, so DOM queries know
the element's props and events:

```ts
const favorite = document.querySelector("favorite-number");
favorite?.value;
//         ^? number | undefined
```

Add the generated server export to a host app and the adapter emits a
declarative shadow template. The browser turns that template into a shadow root
and can paint its contents before it downloads the component bundle. After the
bundle registers the element, the generated extension passes the existing
nodes to Svelte's `hydrate` function.

### TL;DR

Svelte compiles the component and an `HTMLElement` wrapper. The wrapper creates
a shadow root, maps element properties and attributes to component props, and
mounts the component after the browser connects the element.

For server rendering, svebcomponents generates an entry that calls Svelte's
server renderer. A host adapter writes the result into a declarative shadow
template. The browser turns that template into a shadow root before JavaScript
runs.

During upgrade, Svelte's wrapper calls `attachShadow()`. A browser would clear
an existing declarative shadow root before returning it. The svebcomponents
wrapper intercepts that call, preserves the server nodes, and passes them to
Svelte for hydration. Read the [hydration contract](/server-rendering/hydration/)
for fallbacks and limits.
