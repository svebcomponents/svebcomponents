## Scaffold the project

The recommended starting point is the official
[template repo](https://github.com/svebcomponents/template):

<Tabs syncKey="pkg">
  <TabItem label="pnpm">

```bash
pnpm dlx degit svebcomponents/template my-project
cd my-project
pnpm install
pnpm dev
```

  </TabItem>
  <TabItem label="npm">

```bash
npx degit svebcomponents/template my-project
cd my-project
npm install
npm run dev
```

  </TabItem>
  <TabItem label="yarn">

```bash
yarn dlx degit svebcomponents/template my-project
cd my-project
yarn install
yarn dev
```

  </TabItem>
</Tabs>

`dev` starts the SvelteKit app that consumes the component, on
`localhost:5173`.

The template is a small pnpm workspace:

- `components/*` — a Svelte custom element package
- `apps/svelte-kit` — a SvelteKit app that consumes the custom element
- `configs/*` — shared linting, formatting, and TypeScript config

The rest of this page walks through what that component package contains, so
you can also build one from scratch in an existing repo.

## Write the component

A svebcomponent is a Svelte component that declares its own tag. This is the
whole of `src/FavoriteNumber.svelte`:

```svelte title="src/FavoriteNumber.svelte"
<svelte:options customElement="favorite-number" />

<script lang="ts">
  let {
    increments = 1,
  }: {
    increments: number;
  } = $props();

  let count = $state(0);
</script>

<button onclick={() => (count += increments)}>
  add {increments} to {count}
</button>
```

If you know Svelte 5 there is nothing unfamiliar here: typed props, and
`<svelte:options>` to declare the custom element tag.

The one line that matters is the type annotation:

```ts
increments: number;
```

That is enough for
[auto-options](/core-concepts/auto-options/) to generate the prop metadata
Svelte needs to convert the `increments` attribute from a string to a number.
Without it you would write the `customElement={{ props: … }}` object yourself.

## Declare the exports

The `exports` field of the component's `package.json` tells consumers where the
custom element lives — and doubles as the build configuration:

```json title="package.json"
{
  "exports": {
    ".": {
      "types": "./dist/client/FavoriteNumber.d.ts",
      "svelte": "./dist/client-svelte/FavoriteNumber.js",
      "default": "./dist/client/FavoriteNumber.js"
    }
  }
}
```

The `svebcomponents` CLI maps `dist/client/FavoriteNumber.js` back to the
same-basename `src/FavoriteNumber.svelte` and builds that entrypoint. The
`svelte` condition asks for a second, lighter build that Svelte tooling can
select to share the host application's Svelte runtime.

The component file _is_ the entrypoint. Do not add an `index.ts` that
re-exports it: the build would treat that as an ordinary module and skip the
custom-element pipeline entirely.

## Use it

The generated custom element behaves like any other web component:

```svelte
<script lang="ts">
  import "my-components";
</script>

<favorite-number increments={5}></favorite-number>
```

The build also emitted TypeScript declarations for the element. If the package
declares `svelte` as a dependency of its consumers, those are registered with
Svelte's template types automatically, making unknown attributes and
`increments={"nope"}` type errors — see
[Publishing your package](/publishing/#declare-svelte-if-your-consumers-need-it).

:::caution[Pass non-string values as expressions]
Svelte 5 sets attributes as JavaScript properties under certain conditions, so
from a Svelte template use `increments={5}` rather than `increments="5"`. The
first passes the number; the second passes the string `"5"` straight to the
property, bypassing the custom element's attribute converter.

See [sveltejs/svelte#12624](https://github.com/sveltejs/svelte/issues/12624).
:::
