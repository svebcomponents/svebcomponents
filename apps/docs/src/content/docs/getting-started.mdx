You need Node 22 or later. The examples use pnpm; npm and yarn work the same
way.

## Scaffold the project

The recommended starting point is the official
[template repo](https://github.com/svebcomponents/template):

<Tabs syncKey="pkg">
  <TabItem label="pnpm">

```bash
pnpm dlx degit svebcomponents/template my-project
cd my-project
pnpm install
pnpm dev
```

  </TabItem>
  <TabItem label="npm">

```bash
npx degit svebcomponents/template my-project
cd my-project
npm install
npm run dev
```

  </TabItem>
  <TabItem label="yarn">

```bash
yarn dlx degit svebcomponents/template my-project
cd my-project
yarn install
yarn dev
```

  </TabItem>
</Tabs>

`dev` builds the component package in watch mode and starts the SvelteKit app
that consumes it on `localhost:5173`.

The template is a small pnpm workspace:

- `components/example-component` — a Svelte custom element package
- `apps/svelte-kit` — a SvelteKit app that consumes the custom element
- `configs/*` — shared linting, formatting, and TypeScript config

## Read the component

`components/example-component/src/ExampleComponent.svelte`:

```svelte
<svelte:options customElement="example-component" />

<script lang="ts">
  let {
    increments = 1,
  }: {
    increments: number;
  } = $props();

  let count = $state(0);
</script>

<button onclick={() => (count += increments)}>
  add {increments} to {count}
</button>
```

If you know Svelte 5 there is nothing unfamiliar here: typed props, and
`<svelte:options>` to declare the custom element tag.

The one line that matters is the type annotation:

```ts
increments: number;
```

That is enough for
[auto-options](/core-concepts/auto-options/) to generate the prop metadata
Svelte needs to convert the `increments` attribute from a string to a number.
Without it you would write the `customElement={{ props: … }}` object yourself.

## Declare the exports

The `exports` field of the component's `package.json` tells consumers where the
custom element lives — and doubles as the build configuration:

```json title="components/example-component/package.json"
{
  "exports": {
    ".": {
      "types": "./dist/client/ExampleComponent.d.ts",
      "svelte": "./dist/client-svelte/ExampleComponent.js",
      "default": "./dist/client/ExampleComponent.js"
    }
  }
}
```

The `svebcomponents` CLI maps `dist/client/ExampleComponent.js` back to
`src/ExampleComponent.svelte` and builds that entrypoint. The `svelte`
condition asks for a second, lighter build that Svelte tooling can select to
share the host application's Svelte runtime.

## Use it

The generated custom element behaves like any other web component:

```svelte
<script lang="ts">
  import "@svebcomponents/example-component";
</script>

<example-component increments={5}></example-component>
```

Because the package declares `svelte` as a dependency of its consumers, the
Svelte template types are registered for you: unknown attributes and
`increments={"nope"}` are both type errors.

:::caution[Pass non-string values as expressions]
Svelte 5 sets attributes as JavaScript properties under certain conditions, so
from a Svelte template use `increments={5}` rather than `increments="5"`. The
first passes the number; the second passes the string `"5"` straight to the
property, bypassing the custom element's attribute converter.

See [sveltejs/svelte#12624](https://github.com/sveltejs/svelte/issues/12624).
:::
