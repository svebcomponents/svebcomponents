`svebcomponents` can be retrofitted onto any project. The
[starter template](https://github.com/svebcomponents/template) is the quickest
way to get everything set up.

## Start from the template

Clone the [starter template](https://github.com/svebcomponents/template) without Git history with degit:

```bash
pnpm dlx degit svebcomponents/template my-component-library
```

Install its dependencies:

```bash
cd my-component-library
pnpm install
```

### Create the package

Create the component package inside the template's `components` workspace:

```bash
mkdir -p components/cool-counter/src
cd components/cool-counter
```

Add `package.json`:

```json
{
  "name": "cool-counter",
  "version": "0.0.1",
  "type": "module",
  "files": ["dist", "custom-elements.json"],
  "customElements": "custom-elements.json",
  "scripts": {
    "build": "svebcomponents",
    "dev": "vite"
  },
  "exports": {
    ".": {
      "types": "./dist/client/CoolCounter.d.ts",
      "default": "./dist/client/CoolCounter.js"
    },
    "./svelte": {
      "types": "./dist/client/CoolCounter.svelte-types.d.ts"
    }
  },
  "devDependencies": {
    "@svebcomponents/build": "^0.6.0",
    "svelte": "^5.0.0",
    "vite": "^8.0.0"
  }
}
```

svebcomponents maps an export such as `./dist/client/CoolCounter.js` to
`src/CoolCounter.svelte`.

### Write the component

Create `src/CoolCounter.svelte`. Switch tabs to compare the same counter with
svebcomponents and plain Svelte:

<Tabs>
  <TabItem label="After svebcomponents">

```svelte
<svelte:options customElement="cool-counter" />

<script lang="ts">
  let { increments = 1 }: { increments?: number } = $props();
  let count = $state(0);
</script>

<button onclick={() => (count += increments)}>
  add {increments} to {count}
</button>
```

`<svelte:options>` only declares the tag name. Attribute conversion and
reflection are inferred automatically from the TypeScript prop type.

  </TabItem>
  <TabItem label="Before svebcomponents">

```svelte {2-6}
<svelte:options
  customElement={{
    tag: "cool-counter",
    props: {
      increments: { type: "Number", reflect: true },
    },
  }}
/>

<script lang="ts">
  let { increments = 1 }: { increments?: number } = $props();
  let count = $state(0);
</script>

<button onclick={() => (count += increments)}>
  add {increments} to {count}
</button>
```

Plain Svelte requires runtime attribute metadata alongside the TypeScript type.
You maintain both declarations as props change. Without `type: "Number"`,
`increments="5"` arrives as a string.

  </TabItem>
</Tabs>

This comparison covers the component source. svebcomponents also handles the
[package build](/guides/build/) and generates
[consumer types](/guides/framework-types/) and `custom-elements.json`.

### Build it

```bash
pnpm install
pnpm build
```

This invokes the `svebcomponents` CLI, which reads the `$props()` type and
supplies the metadata Svelte's custom element wrapper uses to convert
`increments="5"` to a number. The build produces the browser bundle and
declarations at `dist/client`. It also writes `custom-elements.json` at the
package root.

### Use it

The bundle can be distributed as a package on npm. Consumers only need to
`import "cool-counter"`; the element is registered as a side effect and becomes
available in the DOM, including through
`document.createElement("cool-counter")`.

With the svebcomponents template, add the package as a dependency in
`apps/svelte-kit/package.json` to preview what consumers get:

```json
"dependencies": {
  "cool-counter": "workspace:*"
}
```

Then use it in the app:

```svelte
<script lang="ts">
  import "cool-counter";
</script>

<cool-counter increments={5}></cool-counter>
```

Return to the template root, install the new workspace dependency, and start
the development server:

```bash
cd ../..
pnpm install
pnpm dev
```

Open the local URL printed in the terminal and check out your web component!
